# Симулятор Космической Компании 🚀

Консольный **симулятор управления космической компанией** на **Java 17** —
большой учебный проект по Java Core для подготовки к собеседованиям
QA Automation / SDET.

Ты основываешь компанию, покупаешь ракеты, нанимаешь инженеров/пилотов/учёных,
собираешь экипажи, летаешь на миссии (спутники, грузы, наука, Луна, Марс),
переживаешь случайные события, ведёшь деньги в `BigDecimal` и сохраняешь игру
в текстовый файл. Только чистая Java SE: без Spring, Hibernate и баз данных.

> Проект вырос из крошечного стартера (enum `Rockets` + калькулятор денег).
> Старый enum живёт дальше как `RocketModel` — теперь с топливом, грузом,
> стоимостью запуска и надёжностью.

## Почему код на английском, а доки на русском?

Коротко: **так принято в индустрии**. Ключевые слова Java — английские, весь
мировой код — на английском, на собеседовании попросят читать английский код.
Поэтому: **имена классов/методов/переменных — всегда английские** (это часть
обучения), а всё человеческое — игра, ошибки, доки, обучение — **на русском**.
Деньги в игре — в рублях. Привыкай: через месяц английский в коде перестанет замечаться.

## 1. Что нужно

- **JDK 17+** (любой; разработка шла на OpenJDK)
- **Maven 3.8+**
- Больше ничего. JUnit 5 подтянется сам для тестов.

## 2. Как запустить

**Консоль (терминал):**

```bash
mvn package
java -jar target/SpaceXFromSeverodvinsk-1.0-SNAPSHOT.jar
```

Или запускай класс `org.example.spacecompany.Main` прямо из IDE.

**Ленивый запуск (без длинных команд):**

| Что | macOS / Linux | Windows |
|---|---|---|
| Консоль | `./run-console.sh` | `run-console.bat` |
| Графика (JavaFX) | `./run-ui.sh` | `run-ui.bat` |

## 3. Графическая версия (JavaFX) 🖥️

То же ядро — другое лицо. Архитектура «одно ядро — несколько интерфейсов»:

```
domain / repository / service   ← общее ядро (без JavaFX!)
   ├── console                   ← терминал (был раньше)
   └── ui                        ← JavaFX (новое)
```

Оба интерфейса работают поверх **одного `GameSession`** (репозитории + сервисы).
Контроллеры (`ui/*Controller`) занимаются только показом и вводом: вызывают сервисы
и рисуют результат. Бизнес-логика в UI отсутствует — проверь сам: ни один класс
из `domain`/`service` не импортирует `javafx.*`.

Экраны: **Обзор** (баланс, флот, штат, успешность, свежие полёты и деньги),
**Ракеты** (таблица, покупка, заправка, ремонт, обслуживание), **Сотрудники**
(таблица, найм, увольнение, обучение, отпуск, зарплаты), **Миссии** (создание,
ракета, экипаж, запуск в фоне, журнал полёта), **Финансы** (сводка + операции),
**Статистика** (цифры + диаграмма по статусам). Тема — тёмная минималистичная
(`ui/style.css`: палитра переменными вверху файла, статусы — цветными «пилюлями»).

Цвета есть и в терминале (заголовки, ошибки, номера пунктов — см. `console/Ansi`):
включаются только в живом терминале и гаснут сами в пайпах/файлах.
Принудительно выключить: `NO_COLOR=1 ./run-console.sh`.

Про потоки (учебный пример concurrency): полёт — долгая работа, поэтому запускается
в фоне через `javafx.concurrent.Task` поверх `MissionService.launchAsync` (там свой
`ExecutorService` + `Future`). Правило JavaFX: интерфейс трогаем **только** из
FX-потока — колбэки `setOnSucceeded`/`setOnFailed` уже там, а `future.get()` ждём
в фоне. Подробности — в комментариях `MissionsController`.

**Нативное приложение (двойной клик, без терминала):**

```bash
./package-app.sh        # macOS -> target/dist/SpaceCompany-1.0.dmg
package-app.bat         # Windows -> target/dist/SpaceCompany-1.0.exe
```

Важно: `jpackage` собирает пакет только под **текущую** ОС (кросс-компиляции нет) —
`.exe` собирается на Windows, `.dmg` — на macOS. Неподписанное приложение в macOS
первый раз открывай правым кликом → «Открыть».

## 4. Как запустить тесты

```bash
mvn clean test
```

80 тестов, все зелёные: покупка/топливо/запуск, валидация, математика шансов,
склады, статистика, сейвы, контракты `equals`/`hashCode`, события + сборка ядра
`GameSessionTest`. Тесты не трогают JavaFX-тулкит (интерфейс глазами проверяется
запуском, а логика под ним покрыта unit-тестами).

## 4. Карта проекта для новичка 🗺️

Если потерялся — ты здесь. Проект читается **слоями**, каждый слой знает только
о нижнем. Зависимости текут в одну сторону — стрелки только вниз:

```
┌─────────────────────────────────────────────────┐
│ console    ← лицо №1: меню терминала.           │
│ ui         ← лицо №2: окна JavaFX.              │
│   Оба только показывают и спрашивают!           │
├─────────────────────────────────────────────────┤
│ GameSession ← общее ядро: склады + сервисы.    │
│ service    ← мозги: все правила и решения.     │
│   MissionService, RocketService, FinanceService │
├─────────────────────────────────────────────────┤
│ domain     ← вещи: ракеты, люди, миссии, деньги │
│ repository ← полки: склады хранения             │
│ exception  ← свои ошибки                        │
│ util       ← мелочи: константы, ввод, деньги    │
└─────────────────────────────────────────────────┘
```

**Порядок чтения для новичка (первые 5 файлов):**

| # | Файл | Зачем | Минут |
|---|---|---|---|
| 1 | `spacecompany/Main.java` | увидеть, что запуск — это 5 строк | 2 |
| 2 | `spacecompany/Application.java` | увидеть, как всё собирается вместе | 10 |
| 3 | `domain/Rocket.java` | самый показательный объект: состояние + поведение | 20 |
| 4 | `service/ProbabilityCalculator.java` | чистая математика без магии | 10 |
| 5 | `console/ConsoleMenu.java` | как меню дёргает сервисы | 10 |

Дальше — по интересам (таблица-шпаргалка):

| Хочу понять... | Иди в... |
|---|---|
| наследование, полиморфизм | `domain/employee/` (база `Employee` + 4 профессии) |
| как летает миссия от и до | `service/MissionService.java` (метод `flyMission`) |
| почему миссия не запустилась | `service/MissionValidator.java` |
| откуда берётся шанс успеха | `service/ProbabilityCalculator.java` |
| куда деваются деньги | `service/FinanceService.java` + `domain/Company.java` |
| как игра сохраняется | `service/SaveLoadService.java` |
| случайные события | `domain/event/` + `service/EventService.java` |
| потоки | `service/MissionService.java` (методы `launchAsync*`) + `ui/MissionsController.java` (Task) |
| как устроен графический экран | `ui/` + `resources/ui/` (FXML + контроллер + CSS) |
| что означает любой пакет | `package-info.java` внутри него — там подсказки на русском! |

> 💡 В каждом пакете лежит файл `package-info.java` — короткое описание на русском:
> что внутри и с чего начать. В IDE они показываются при наведении на пакет.

**Главные запреты архитектуры** (если нарушил — ты заблудился):
- меню не хранит деньги и не проверяет правила — оно только спрашивает и печатает;
- сервисы не рисуют текст в консоль (кроме возврата данных) — они решают;
- домен-объекты не знают про сервисы и файлы — они охраняют своё состояние.

## 5. Игровой цикл

1. Назови компанию (стартуешь с 20 000 ₽, подаренной Falcon 9 и двумя специалистами).
2. **Обзор компании** — баланс, флот, штат, недавние полёты.
3. **Ракеты** — купи (`Falcon 1/9/Heavy`, `Starship`), заправь, отремонтируй.
4. **Сотрудники** — найми `Engineer` / `Pilot` / `Scientist` / `Mission Specialist`,
   обучай, отправляй в отпуск, плати зарплаты.
5. **Миссии** — создай (спутник, груз, наука, Луна, Марс), назначь ракету и экипаж,
   проверь готовность, **запускай**.
6. Заработал или потерял — чини ракету, лети снова.
7. **Финансы** — история операций, итоговая прибыль.
8. **Статистика** — доля успеха, группировки, лучшие люди и ракеты.
9. **Сохранить / загрузить** — обычный текстовый файл (`space-company-save.txt`).

## 6. Архитектура

```
org.example.spacecompany
├── Main                  # тонкий запуск консоли, логики нет
├── Application           # консоль: спрашивает имя, запускает меню
├── GameSession           # ОБЩЕЕ ЯДРО: склады + компания + все сервисы;
│                         # поверх него работают и консоль, и JavaFX
├── domain                # состояние + поведение, без ввода/вывода
│   ├── Company           # корень: баланс, проводки, история полётов;
│   │                     # содержит три склада (композиция, не наследование)
│   ├── Rocket / RocketModel / RocketStatus
│   ├── employee: Employee (абстрактный) → Engineer, Pilot, Scientist, MissionSpecialist
│   ├── mission: Mission / MissionType / MissionStatus / MissionResult (record)
│   ├── finance: Transaction (неизменяемая) / TransactionType
│   └── event: GameEvent (интерфейс) + 6 реализаций + EventContext
├── exception             # непроверяемые бизнес-ошибки + 1 проверяемая (файлы)
├── repository            # Repository<T,ID> → репозитории ракет/людей/миссий
│                         # InMemory* на ConcurrentHashMap
├── service               # бизнес-логика (меню в склады не лезет)
│   ├── FinanceService / RocketService / EmployeeService
│   ├── MissionValidator (статические правила) / ProbabilityCalculator (чистая математика)
│   ├── MissionService (обычные + фоновые запуски на ExecutorService)
│   ├── EventService (подключаемые случайные события)
│   ├── StatisticsService (циклы + стримы)
│   └── SaveLoadService (java.nio.file, try-with-resources, свой текстовый формат)
├── console               # лицо №1 (терминал): ConsoleMenu + 5 подменю + MenuIO
├── ui                    # лицо №2 (JavaFX): FxLauncher, 7 FXML + контроллеры,
│                         # Dialogs, тёмная тема style.css; логики нет, только показ
└── util                  # GameConfig (константы), MoneyUtils, InputReader
```

Принципы: консоль вводит/выводит, сервисы решают, объекты guard'ят своё состояние,
склады хранят. Без god-классов, без статического изменяемого состояния, без циклов
зависимостей. Деньги — `BigDecimal`, id — `UUID`, время — `java.time`.

## 7. Карта Java Core → проект

| Кусок проекта | Тема Java Core |
|---|---|
| `RocketModel`, `MissionType`, `RocketStatus`, … | `enum` с полями/конструктором/`switch` |
| `Rocket`, `Company` | инкапсуляция, `this`, конструкторы, перегрузка |
| `Employee` → `Engineer/Pilot/…` | наследование, `super`, переопределение, полиморфизм, абстрактные классы |
| `GameEvent` + реализации | интерфейсы, открытость/закрытость без фреймворков |
| `Repository<T, ID>` | generics, wildcard'ы (`? extends Employee`) |
| `equals/hashCode/toString` в домене | контракт равенства (тест `DomainEqualityTest`) |
| `List<Rocket>`, `Set<UUID>` экипажа, `Map<MissionStatus,Long>`, `ConcurrentHashMap` | коллекции + конкурентные коллекции |
| `StatisticsService`, поисковики | Stream API, лямбды, method references (вперемешку с циклами — специально) |
| `Optional` в складах/сервисах | `Optional` вместо null'ов |
| иерархия `SpaceCompanyException` vs `GameSaveException` | непроверяемые vs проверяемые исключения |
| откат в `flyMission`, остановка в `Application.run` | `try/finally` там, где надо |
| `SaveLoadService`, `InputReader` | `java.nio.file`, try-with-resources |
| `MissionResult` | `record` (компактные неизменяемые данные) |
| `launchAsync/launchAllReady` | `ExecutorService`, `Callable`, `Future`, `CompletableFuture`, `synchronized`, `AtomicInteger` |
| `Company.deposit/withdraw` | `synchronized`-методы + денежная математика `BigDecimal` |
| метки времени, `Duration` полёта, даты найма | `java.time` |
| `InputReader.readInt`, меню | циклы, `switch`, разбор строк |
| `MissionResult`, `Transaction` | неизменяемость (`final`, немодифицируемые списки) |

Подробно — **[LEARNING.md](LEARNING.md)** (теория с ловушками и вопросами).

## 8. Как устроено обучение

```
src/main/java/.../spacecompany/   # 80+ файлов — рабочий ЭТАЛОН (спойлер!)
src/main/resources/ui/            # 7 FXML + тёмная тема style.css
src/test/java/.../                # 13 файлов, 80 тестов
quests/Quest00..Quest06.java       # полигоны с TODO — код пишешь ТЫ
ROADMAP.md                         # 70+ уровней, звания, XP, боссы
LEARNING.md                        # теория на русском
```

Правило: сначала пишешь сам (полигон или уровень), потом сверяешься с эталоном.
Подглядел раньше — минус ачивка «Честный инженер» 🙂

## 9. Что учить первым

1. `domain/Rocket.java` — богатый объект: состояния, поведение, равенство.
2. `domain/employee/Employee.java` + один наследник — наследование как надо.
3. `service/ProbabilityCalculator.java` — чистая функция, легко тестировать.
4. `service/MissionService.java` — оркестратор: валидация → деньги → статусы →
   события → `try/finally`-откат → `ExecutorService`.
5. `service/SaveLoadService.java` — файлы, экранирование, парсинг `java.time`.
6. Дальше — `ROADMAP.md`, уровень за уровнем.

## 10. Куда развивать дальше
